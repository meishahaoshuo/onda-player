# 会话 2：跳转过渡重做为「引力坍缩」

## 今日完成
- **方案迭代**：用户反馈第一版 FLIP"不够创新"，经两轮交互式演示（8 个方案）与确认，最终从「G 相机推进 + F 声波涟漪 + 取色晕开」的混合方案改为**「引力坍缩」**（用户拍板：去掉涟漪环，采用引力坍缩）。
- **编排器重写**（`src/services/pageTransition.ts`）：`beginAlbumEnter` / `playAlbumEnter` / `playAlbumExit` / `clearTransitionState`。
  - 进入：周边卡片按"到点击点距离"依次被**吸入点击点**（translate+scale0.22+±8~18° 旋转+淡出，420ms）；被点卡片淡出让位；**详情页从被点卡片矩形析出放大**接管整页（transform-origin 钉卡片左上角，460ms）；封面 FLIP 飞向头部大图（540ms）；内容按距离波前依次浮现（删除写死的 40/80/120ms）。
  - 返回对称反向：内容反序收起 → 详情层折叠回卡片矩形再收缩消失 → 卡片从坍缩点喷回（延迟取反）→ 封面飞回卡片 → 被点卡片淡回。
  - 降级：`prefers-reduced-motion` 仅淡入；`hardwareConcurrency<=2` 或首帧探针 <50fps 进 lite 档（时长 ×0.7）。
- **详情层架构调整**：`AlbumDetailView` 从 `<Transition name="view">` 的 `:key=activeView` 区块移到 `.content` 内绝对定位覆盖层（`.detail-layer`）。原因：网格→详情是同 view 内 `detailKey` 切换，外层 Transition 不触发，且 v-if 会让网格立刻卸载无法参与动画。网格常驻 → 滚动位置与卡片 DOM 全保留，返回无需重定位。App.vue 的 albums 分支退化为 `<AlbumsView v-else-if>`（保持 v-if 链连续）。
- **封面主色预取服务**（新增 `src/services/paletteCache.ts` + `palette.coverBaseColor`）：LRU 64、并发 3、可视区卡片 idle/滚动 debounce/hover 插队；`--ambient-fallback` 兜底。详情页环境光晕改为"开场即用预取主色铺底 + 落定后换 `renderAmbientUrl` 预烘焙 PNG"，并**去掉 `.header-ambient` 的实时 `blur(56px)`**（对齐歌词页做法，避免全屏 blur 并行栅格化卡顿）。
- 旧 FLIP 逻辑抽到 `src/services/legacyFlip.ts`，艺术家/歌单两页继续使用（后续可迁移后删除）。
- `ui` store 新增 `dolly` 状态（idle/enter/exit，兼作连点闸门）。

## 遇到的问题（关键坑，务必记住）
- **先量后动**：任何 rect 必须在变换开始前测。曾犯两处错：详情层推进缩放途中量头图矩形（落点错位）；被点卡片参与后退变换导致返回落点错。解法：被点卡片**不参与**几何变换、只淡出让位；层做纯几何折叠不做中途测量。
- **`overflow` 容器杀 3D**：`.view-body` 是 `overflow-y:auto`，`preserve-3d` 会被强制 flat，共享 3D 空间断裂——故弃用祖先 perspective 方案（这也是最终没走"相机推进"的技术原因之一）。
- **dolly 状态没有复位路径**会让返回按钮永久锁死——`playAlbumEnter` 结束必须 `endDolly()`。
- WAAPI 动画优先级高于普通声明，天然压过 `:hover` transform，避免与卡片 hover 位移打架。

## 验证
- `npm run build`（vue-tsc + vite）零错误。待用户真机实测：吸入编排、析出节奏、返回闭环、滚动后返回落点、大歌库流畅度。

- 用户实测手感后微调：吸入旋转幅度 / 析出时长 / 波前密度。

# 会话 25：修复专辑网格过渡竞态导致的大面积空白

## 根因
点开详情时视口内 ≤24 张卡片被打上 `fill:'forwards'` 的坍缩动画（终态 opacity:0），正常返回由 restoreGrid 取消还原；但详情打开时点侧边栏**当前视图**（navigate 同视图只改 detailKey、activeView 不变）→ App.vue 只监听 activeView 变化才清理 → 详情层瞬间卸载、返回过渡没跑，孤儿 fill 动画永久挂在卡片上 → 大面积空白（视口外/超上限的卡片可见）。且 gridRecs 被下次进入覆盖后旧动画引用丢失，之后正常开关也无法自愈。

## 修复（pageTransition.ts + App.vue + 两个详情视图）
1. App.vue 增加 `watch(detailKey)`：key→null 时强制 `clearTransitionState()`（堵住导航洞）。
2. pageTransition 加 `epoch` 代际号：begin/exit/clear 自增；`playAlbumEnter` 在 flyCover await 后、`playAlbumExit` 在 await 后核对代际，过期续段立即收手（不动 dolly）。
3. `allAnims` 全量动画登记表 + `track()`：finish 不移除（fill 仍持有样式）、cancel 才移除；clearTransitionState 一网打尽。
4. `resetGridCards()` 强制复位：取消卡片上一切动画+行内残留；beginAlbumEnter 先复位再测量（先量后动永远成立），clear 时也调。
5. 退出收尾（clearTransitionState/closeDetail/endDolly）移入 playAlbumExit，完成才执行；AlbumDetailView/ArtistDetailView 的 close() 不再自行收尾。
6. AlbumsView onBeforeUnmount 无条件 clearTransitionState（原 dolly==='idle' 条件去掉）。

## 验证（headless CDP + testBridge 新增 stressAlbums(40) 注入）
- 场景A 进入中途侧边栏抢断×8（80~465ms 递增时机）：badCount 全 0。
- 场景B idle 后抢断×3、场景D 返回中途跨视图抢断：全 0 残留。
- 场景C 正常开关×3：开 24 张坍缩动画（正常）、关 0 残留、dolly 归位 idle。
- 15 轮审计 0 失败、0 异常。截图 devlog/.shots-2026-09-05/transition-stress-final.png。

## 踩坑
- 同一文件多个 Edit 并行调用会写入竞态（last-writer-wins），pageTransition.ts 一度半新半旧（close 收尾丢失→dolly 卡 exit、详情层僵住）；教训：同文件编辑必须串行。
- getAnimations()/document.getAnimations() 会列出已 finish 但 fill≠none 的动画，可作为「孤儿 fill」的审计信号。

# 会话 37：歌词卡拉OK改 Apple Music 式逐字点亮

## 背景与根因
用户反馈卡拉OK逐字效果「和正常音乐播放器有出入」。排查确认三个根因：
1. **整行线性推进**：旧实现用 `(t - 当前行time) / (下一行time - 当前行time)` 把整行当均匀进度条从左刷到右，填充速度与唱词节奏无关；
2. **硬边界**：CSS 两个同值 stop 的 hard-stop 渐变，填充前沿是锐利竖线；
3. **逐字数据被丢弃**：`parseLrc` 直接 `replace(WORD_TAG, '')` 剔除增强型 LRC 的 `<mm:ss.xx>` 标签。

## 实现
- **解析层**（`src/services/lyrics.ts`）：`LyricGroup` 新增 `charTimes?: number[]`（与 texts[0] 逐码点对齐的开始时刻，末位为行尾时刻）。词标签切段后**词内字符线性均分**区间；行尾时刻按词均长估算（最短 0.6s）；trim 首尾空白并同步修正首/末词长度；码点数对不上时放弃逐字（防御）。普通 LRC 不生成 charTimes。
- **视图层**（`LyricsFullView.vue`）：
  - active 行主文本按码点拆 `<span class="lyric-char">`；非 active 行/翻译子行保持整行渲染。
  - rAF 引擎重写，**DOM 直写绕开 Vue 响应式**：已唱字符一次性补 100%、每帧只写当前字符 `--cp`；音频时间倒退 >50ms（行内回 seek）或 force 时全行重刷。
  - 无 charTimes 时**虚拟插值兜底** `virtualCharTimes`：CJK 1.0 / 拉丁数字 0.6 / 空白 0.3 / 其它 0.5，句读标点后 +0.8 停顿权重，把行时长加权分配到各字符。
  - `groups` computed 的 lyricOffset 平移现在**同步平移 charTimes**。
  - `syncKaraoke()`：换行/歌词重载/暂停 seek 后重建 span 引用并全量刷填充态。
- **CSS**：`.lyric-char` 字符级三停渐变 `激活色 calc(var(--cp) - 12%) → 混合中间色 var(--cp) → 未唱色 +12%`，填充前沿约 0.12 字宽柔光；中间色用 `color-mix`（Chrome 目标可用），全部引用现有 `--lyric-*` 令牌。

## 顺手修的存量 bug
`syncLyricRaf` 里 `cancelAnimationFrame(lyricRaf)` 后**未归零**——暂停一次后 `lyricRaf` 恒为真，暂停态兜底 watcher 的 `if ( lyricRaf) return` 永久短路：暂停后 seek 不再更新行高亮与逐字态（旧版同样存在，只是旧版只影响行高亮）。已加 `lyricRaf = 0`。

## 验证（IAB 浏览器 + dev 测试桥，5180）
- 解析：页面内直接 `parseLrc` 增强样例 → charTimes `[0.3,0.45,0.6,0.675,...,1.8]` 与设计一致。
- 增强型 LRC：t=0.5 → `[100,33.3,0×9]`（回退 seek 正确重刷）；t=1.5 → 换行 3 字符 `[100,50,0]`；t=0.85 → 空格符 33.3%，逐字精确对齐。

# 会话 38：修复歌词页飞入过渡结尾封面顿挫

## 根因
用户反馈：首页点小封面进歌词页，过渡结尾封面「顿一下、挪一下」。两个叠加原因：
1. **视差错位**：`.cover-main` 挂鼠标视差 `translate: calc(var(--mx)*-6px) calc(var(--my)*-5px)`（无过渡瞬跳）。打开歌词页后鼠标微动即写入 --mx/--my（设在 `.lyrics-full` 根上），真实封面立刻偏移；而飞行克隆挂在 `document.body` 上**吃不到页面级 CSS 变量**，飞向未偏移位置 → 交接瞬间两者错位最多 6px。
2. **克隆样式写死**：克隆 `border-radius:12px; box-shadow:none`，真实封面是 10px 圆角 + `0 20px 48px` 投影，交接时投影突现加重顿挫。

## 修复（LyricsFullView.vue 三处）
1. `onPageMouseMove` 加守卫：`flyActive || closing` 时 return——飞行/关闭过渡期间冻结视差。
2. `.layout.fly-active .cover-main` 补 `translate: none`（与既有 `transform: none` 并列），CSS 层双保险。
3. 克隆的 `borderRadius`/`boxShadow` 改为 `getComputedStyle(dstInner)` 读取真实值，交接无样式突变。

## 验证（IAB 浏览器逐帧采样）
- 复现路径（点播放条小封面）+ 飞行期间每 50ms 派发 mousemove 干扰：
  - 飞行中真实封面漂移 **0.0px**（视差冻结生效）；
  - 克隆末帧 (132.0, 148.1, w388.8) vs 交接后真实封面首帧 → **Δx=0, Δy=0, Δw=0**（亚像素一致）。
- 回归：非飞行期视差正常（右上↔左下位移 10.9/-8.2px，与 ±6/±5 公式吻合）；关闭飞回正常（lyricsOpen 正确复位）；落定截图封面带投影无异常。
- `npm run build` 零错误。

## 测试环境备注
- IAB 标签页在后台时 rAF 停转，rAF 采样循环会卡死 evaluate——采样前先用 visibility capability 把面板调到前台。
- 无用户激活时 `library.rescan()`/`audio.play()` 会抛 NotAllowedError（策略拦截）；`playAt` 抛错但 current/coverId 状态已设置，测试飞行动画不需要真出声。
