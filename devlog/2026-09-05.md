# 会话 2：跳转过渡重做为「引力坍缩」

## 今日完成
- **方案迭代**：用户反馈第一版 FLIP"不够创新"，经两轮交互式演示（8 个方案）与确认，最终从「G 相机推进 + F 声波涟漪 + 取色晕开」的混合方案改为**「引力坍缩」**（用户拍板：去掉涟漪环，采用引力坍缩）。
- **编排器重写**（`src/services/pageTransition.ts`）：`beginAlbumEnter` / `playAlbumEnter` / `playAlbumExit` / `clearTransitionState`。
  - 进入：周边卡片按"到点击点距离"依次被**吸入点击点**（translate+scale0.22+±8~18° 旋转+淡出，420ms）；被点卡片淡出让位；**详情页从被点卡片矩形析出放大**接管整页（transform-origin 钉卡片左上角，460ms）；封面 FLIP 飞向头部大图（540ms）；内容按距离波前依次浮现（删除写死的 40/80/120ms）。
  - 返回对称反向：内容反序收起 → 详情层折叠回卡片矩形再收缩消失 → 卡片从坍缩点喷回（延迟取反）→ 封面飞回卡片 → 被点卡片淡回。
  - 降级：`prefers-reduced-motion` 仅淡入；`hardwareConcurrency<=2` 或首帧探针 <50fps 进 lite 档（时长 ×0.7）。
- **详情层架构调整**：`AlbumDetailView` 从 `<Transition name="view">` 的 `:key=activeView` 区块移到 `.content` 内绝对定位覆盖层（`.detail-layer`）。原因：网格→详情是同 view 内 `detailKey` 切换，外层 Transition 不触发，且 v-if 会让网格立刻卸载无法参与动画。网格常驻 → 滚动位置与卡片 DOM 全保留，返回无需重定位。App.vue 的 albums 分支退化为 `<AlbumsView v-else-if>`（保持 v-if 链连续）。
- **封面主色预取服务**（新增 `src/services/paletteCache.ts` + `palette.coverBaseColor`）：LRU 64、并发 3、可视区卡片 idle/滚动 debounce/hover 插队；`--ambient-fallback` 兜底。详情页环境光晕改为"开场即用预取主色铺底 + 落定后换 `renderAmbientUrl` 预烘焙 PNG"，并**去掉 `.header-ambient` 的实时 `blur(56px)`**（对齐歌词页做法，避免全屏 blur 并行栅格化卡顿）。
- 旧 FLIP 逻辑抽到 `src/services/legacyFlip.ts`，艺术家/歌单两页继续使用（后续可迁移后删除）。
- `ui` store 新增 `dolly` 状态（idle/enter/exit，兼作连点闸门）。

## 遇到的问题（关键坑，务必记住）
- **先量后动**：任何 rect 必须在变换开始前测。曾犯两处错：详情层推进缩放途中量头图矩形（落点错位）；被点卡片参与后退变换导致返回落点错。解法：被点卡片**不参与**几何变换、只淡出让位；层做纯几何折叠不做中途测量。
- **`overflow` 容器杀 3D**：`.view-body` 是 `overflow-y:auto`，`preserve-3d` 会被强制 flat，共享 3D 空间断裂——故弃用祖先 perspective 方案（这也是最终没走"相机推进"的技术原因之一）。
- **dolly 状态没有复位路径**会让返回按钮永久锁死——`playAlbumEnter` 结束必须 `endDolly()`。
- WAAPI 动画优先级高于普通声明，天然压过 `:hover` transform，避免与卡片 hover 位移打架。

## 验证
- `npm run build`（vue-tsc + vite）零错误。待用户真机实测：吸入编排、析出节奏、返回闭环、滚动后返回落点、大歌库流畅度。

## 明日待办
- 用户实测手感后微调：吸入旋转幅度 / 析出时长 / 波前密度。
- 艺术家/歌单详情迁移到同一编排器后删除 `legacyFlip.ts`。
