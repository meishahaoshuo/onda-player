### 桌面玻璃重做：整窗 Acrylic 磨砂（同会话第三项）

用户诉求：播放器实现截图那种「整窗透明磨砂、透出桌面壁纸」的效果（对照某播放器截图）。经讨论拍板：整窗 Acrylic（非 Mica）、设置→外观加开关默认开、歌词页保持不透明沉浸；用户特别要求**每个页面适配完善、不留明显短板**。

- **翻车史先行**：9.5 做过同款，9-15 整体回退——真机量出深色页面底色恰好 #454545 = 0.76×#0a0a0a + 0.24×白，证明那 24% 透明缝隙底下压着的是 webview 图层的**不透明白**（材质从未真正可见）。本次重做把两个漏白点在结构上堵死：① 主窗口配置补 `transparent: true` + `backgroundColor: "#00000000"`（本地 config.schema 查证：backgroundColor **同时作用于窗口层与 webview 层**，alpha 非 0 时 webview 层忽略 alpha——配置层即可解决，无需 Rust builder）；② 回退时加的「html 元素同步写不透明底色防闪白」逻辑在玻璃态改为写 `transparent`（它压在材质与 body 之间，不透明会盖死材质——上次的第二个漏白点）。index.html 防闪脚本不动：它写的不透明底只存在于启动过场期间，且过场 backdrop 本就不透明。
- **实现**：Cargo.toml 加回 `window-vibrancy = "0.6"`；lib.rs 恢复 `set_window_effect(enabled, dark)`（开=apply acrylic / 关=clear，一个命令管开关与主题）；settings store 新增 `desktopGlass`（`settings.desktopGlass`，默认开）+ watchEffect 分支写 html 底色并调 `desktop.setWindowGlass`（挂/摘 `html.desktop-glass` + invoke Rust；apply 失败自动摘类降级不透明实底；开关与主题切换都经同一条 watchEffect 路径，无需单独 data-theme 观察器）；main.css 恢复 `html.desktop-glass body { background: color-mix(in srgb, var(--bg-base) 76%, transparent) }`；SettingsView 外观分类新增「桌面玻璃→窗口磨砂」AppSwitch（仅桌面显示）。
- **全页面适配审计**（用户硬要求）：逐表面确认——歌曲/专辑/艺术家/排行榜/我喜欢的/最近在听/文件夹/搜索/歌单网格/设置全部是透明叠 body，自动获得磨砂底；`.detail-layer`/`.playlist-detail` 详情覆盖层与歌词页/启动过场**保持不透明**（代码注释明示：覆盖层与 body 之间夹着常驻网格，半透明会穿透出来——它们盖的是页面内容不是窗口，属结构性设计而非适配疏漏）；侧栏/播放条/顶栏玻璃层正好坐在磨砂上；二级弹层维持纯色规则；托盘浮层独立透明窗口不受影响。
- **验证**：`vue-tsc` + vite build 通过、`cargo check` 通过；浏览器形态回归（IAB 实测）无 glass 类、html/body 不透明、设置页无桌面区块——零变化；真机（WebView2 CDP 9223）11 项断言全绿：类挂载 / html 透明 / body 76%（浅=白 76%、深=#0a0a0a 76%）/ 摘类↔挂类往返（注意 body 有 380ms 背景过渡，读样式必须等过渡收尾）/ Rust apply_acrylic 深浅两 tint 回执均 Ok / localStorage 切深色 reload 全链路 / 桌面设置页开关出现。主题设置已恢复 system。
- **坑备忘**：①WebView2 对同一用户数据目录会**复用既有浏览器进程**，新加的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 对已存在进程无效——CDP 调试前要先杀掉 ours 的 msedgewebview2（按命令行匹配 `ondaplayer` 定向清理，勿全杀，别的应用也在用 WebView2）；②`tauri dev` 的 npm 包装进程可能先行退出而 app.exe 存活，验证以进程和窗口为准；③Chrome 对 color-mix 的 computed style 序列化是 `color(srgb r g b / a)` / `oklab(...)`，断言要解析 alpha 而非匹配字面量。

### 桌面玻璃第二轮：全局统一低透明（同会话用户反馈迭代）

用户真机反馈：通透效果差、各模块通透程度不同、适配不完善，要求**全局透明**；并强调改动不得影响非玻璃模式的观感。

- **诊断（为什么看着不透）**：透明度是**叠乘**的——首版 Acrylic tint alpha 125/150（≈49%/59%）× body 76% × 面板 66% → 面板处总不透明度 ≈95%，且各模块叠乘路径不同（详情层还是 100%）→「每个地方透得都不一样」。
- **统一低透明体系**（全部限定 `html.desktop-glass` 作用域，非玻璃态零变化）：① Rust tint 压低为深 `(14,14,18,90)`≈35% / 浅 `(242,243,245,105)`≈41%；② body 基底 76% → 深 55% / 浅 50%（新令牌 `--glass-body-mix` 入主题块）；③ 玻璃态下把 `--bg-panel`→`--glass-panel-bg`（浅 0.26/深 0.30）、`--glass-bg`→`--glass-chrome-bg`（低 alpha 渐变），总不透明度收敛 ~70%，面板/铬层/基底梯度收窄。**坑**：令牌覆盖最初写 `html.desktop-glass` (0,1,1)，被主题块 `:root[data-theme]` (0,2,0) 压住静默无效——升为 `html:root.desktop-glass` (0,2,1) 才生效（CDP 读 `--bg-panel` 仍 0.66 抓出来的）。
- **详情覆盖层透明化**（用户要全局，推翻上一轮「保持不透明」决策）：`.detail-layer`/`.playlist-detail` 玻璃态 `background: transparent`；网格穿透问题用 dolly 生命周期解决——App.vue 新增 `glassGridHidden` computed（`isDesktop && desktopGlass && detailKey && dolly==='idle'`）给 `.view-body` 挂 `.glass-grid-hidden`（`visibility:hidden`，保布局与滚动记忆）；开场坍缩（'enter'）与返回折叠（'exit'）期间自动恢复，网格照常参与过渡，完全不动 pageTransition 编排器。
- **验证**：CDP 断言 11 项全绿——body 0.50/0.55、面板 0.26、铬层低 alpha、详情层透明、落定藏网格/折叠起步恢复、关开关后面板精确回 0.66 + body 不透明（非玻璃观感零变化的实证）；`vue-tsc` + `cargo build` 通过。观感继续由用户真机确认（不透明度梯度如需再调，改主题块里三个 `--glass-*` 令牌 + lib.rs tint 四个数字即可）。
