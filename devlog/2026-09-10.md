## 1. 液态玻璃（播放条）透明度与折射感增强

需求：把液态玻璃的透明度和折射感再往上拉一些。

改法（`PlayerBar.vue`，仅调 `material-liquid` 及其胶囊边框块，深浅双主题）：

- **深色**：`blur(18px) saturate(3) brightness(1.16)` → `blur(20px) saturate(3.6) brightness(1.2)`；白纱 alpha `0.06/0.03/0.05` → `0.03/0.015/0.025`（更透）；顶缘高光 `0.55 → 0.62`、新增 `inset 0 -1px 0 rgba(0,0,0,0.16)` 下缘暗线（玻璃厚度）。
- **浅色**：`blur(16px) saturate(2.4) brightness(1.03)` → `blur(18px) saturate(3.1) brightness(1.05)`；白纱 `0.13/0.07/0.11` → `0.08/0.04/0.065`；内高光 `0.9 → 0.95`、内环 `0.45 → 0.5`。
- **胶囊边框（液态玻璃）**：深色边 `0.3 → 0.38`、顶高光 `0.55 → 0.7`；浅色边 `0.09 → 0.1`、内高光 `0.9 → 0.98`、内环 `0.45 → 0.6`。强化边缘「玻璃厚度 / 折射」感。
- 只动视觉像素值；材质切换 transition（background/box-shadow/backdrop-filter 420ms）与其它逻辑未改。

**两个调节杠杆**（后续微调直接改这里）：
- 透明度 = 白纱 `background` 的 alpha（越低越透）
- 折射感 = `backdrop-filter` 的 `saturate()`（越高背后颜色越浓）+ 顶缘/内环高光强度

构建通过（dist 已重建，CSS 产物 grep 确认 `saturate(3.6)`/`saturate(3.1)` 各 2 处，对应标准与 `-webkit-` 前缀）。

## 2. 修复「切板块时上半列表刷新、下半还在」（错峰浮现被反复重放）

**现象**：左侧板块之间切换时，歌曲列表前一部分像在"刷新"，后一部分已经在了。

**诊断（CDP 真机复现，Chrome headless + Vite dev server）**：
- 先排除了结构性叠加：遍历 8 个板块 + 快速连点（60ms 间隔打断过渡）+ 专辑详情切换 + 歌单切换，`.view-body` 恒为 1 个、无 detail-layer 残留、虚拟窗口与滚动位置同步（`derivedStart == expectStart`）、无 console 异常 → 不是双视图叠加（区别于 2026-09-01 那条 v-if 链断开的旧 bug）。
- **真因**：探针（`getAnimations()` + computed opacity）抓到切换后 120ms 时**前 14 行带 `.stagger-row` 且 opacity=0 正在浮现，第 15 行起 opacity=1 立刻可见**。即 `SongList` 的「首屏错峰浮现」在每次切板块（SongList 重挂载）时被重放，且只覆盖前 `MAX_REVEAL_ROWS(14)` 行 → 视觉上就是"上半刷新、下半还在"。

**根因（Vue 坑）**：`<script setup>` 里的顶层变量会被编译进 `setup()`，**每个组件实例各一份**。所以最初把 `revealPlayed` 写成脚本顶层的模块级变量并不生效——每次挂载仍重置为 false。

**修法**：
- `src/composables/useStaggerReveal.ts` 新增真正的模块作用域闸门 `claimListReveal()`（`let` 声明在模块顶层，导出函数闭包访问）：会话首次调用返回 true，之后恒 false。
- `src/components/SongList.vue`：`booting` 改为由 `claimListReveal()` 领取，只有会话首个列表挂载播一次错峰浮现；此后切板块一律直接显示，上下半表现一致。

**验证**（`onda-switch-verify7.mjs`）：
- 切「设置」→「歌曲」、切「专辑」→「歌曲」后 120/420/720ms 采样：`staggerRows=0`、可见行 opacity 全为 1 ✓（修复前为 14 行 animating / opacity 0）。
- 整页重载后轮询：t=250/500/750ms `staggerRows=14`（animating 14→13→6），t≥1000ms 归 0 → **会话首次挂载仍保留一次错峰浮现** ✓。
- 截图 `fix-switch-back-420.png` 目检：可见 11 行全部正常。

**另发现（未改，待用户确认是否要修）**：
1. 搜索时 `.view-body` 不重建（`:key="ui.activeView"` 不变），会**继承上一个列表的 scrollTop** → 搜索结果条数较多时会从中段开始显示（实测 scrollTop 2788）。
2. 侧栏点歌单走 `Sidebar.openPlaylist()` 直接改 `activeView/detailKey`、**未清 `searchQuery`** → 搜索词还在时点歌单，内容区仍停在搜索结果上。

构建通过（dist 已重建）。
