## 会话 20（两个体验问题修复：歌词页转场 + 封面画质）

### 用户反馈
1. 歌词页飞入动画收尾有明显的"顿一下"——怀疑是缓动曲线或主线程阻塞
2. 歌词页封面太糊，看起来像低分辨率缓存图，怀疑没加载正确尺寸的源

### 根因分析

**封面画质**：`src/services/scanner.ts` 的 `makeThumb` 把封面缩到**最长边 256px** 的 JPEG 写入 IndexedDB 供全站使用；歌词页 CSS 把封面渲染为 `min(42vh, 30vw)`（1080p 屏约 453px CSS，DPR2 屏要 906 设备像素）—— 256px 源直接糊。

**动画收尾顿挫**：`flyIn` 用 WAAPI 同时动画 `left/top/width/height`——这些是**布局属性**，每帧都触发布局重算；页面上还有 `blur(70px) scale(1.35)` 的全屏背景和 `backdrop-filter: blur(46px)` 的迷你条，布局变化会强制让这些大模糊层重新栅格化，收尾时尤其明显。叠加三个并发问题：
- 落地瞬间 `.cover-col` 的 300ms 切歌淡入还在进行（opacity ≈ 0.87→1）→ 视觉上像闪一下
- 飞行期间歌词列表的 mask + 逐行 blur 在做 700ms 的 smoothScroll
- 全屏 blur 背景的 520ms 淡入由 immediate watch 在飞行前就触发了，rasterization 卡在飞行开始附近

### 修复

**封面（按需高清提取 + 切歌预热）**
- 新增 `src/services/cover.ts`：`extractHiResCover(song)` 从音频内嵌图直接 parse（`duration: false, skipPostHeaders: true`，只解析头部），最长边缩到 1024px JPEG q0.92；空封面/失败返回 null
- `library` store 新增 `coverUrlHi(coverId)`：内存 LRU（上限 32，超出回收最早的 objectURL），同 coverId 并发去重
- `CoverImage` 加 `hires` prop：先挂 256px 缩略图立即有画面，再静默换高清图（`img.decode()` 完成后再替换 src，替换瞬间即可见，无二次解码闪烁）
- `PlayerBar` 监听 `player.current.coverId`，用 `requestIdleCallback` 预热当前曲目的高清图——打开歌词页秒出，flyIn 不再等它
- 专辑详情头部封面同步加 `hires`（192px 在 DPR2 屏同样偏软）

**动画（transform-only FLIP + 全程不抢主线程）**
- `flyIn` 改为**只动 transform** 的 FLIP：克隆**目标**封面（不是播放条小图，确保落地时是同一张图，零内容/清晰度跳变），按目标尺寸铺在终点，用 `transform: translate + scale` 反向缩回起点，再动回单位矩阵。Easing 从 `cubic-bezier(0.22, 1, 0.36, 1)`（easeOutQuint，尾段近乎静止）换成 `cubic-bezier(0.32, 0.72, 0, 1)`（Apple sheet 标准减速曲线，收尾干脆）
- 飞行期间 `.cover-col` 不参与切歌淡入淡出（新增 `.main.fly-active .cover-col { opacity:1; transition:none }`），避免落地瞬间还在半透明
- 飞行期间跳过歌词 smoothScroll（落地后用 `scrollToActive(false)` 一次性直接定位，无 700ms 过渡）
- 背景渐变：飞行期间不挂 DOM（`v-if` 的 `bgUrl` 在飞行中保持 null），落地后才插入并淡入——把全屏 blur 的栅格化挪到转场之后
- `bg-grad` 的 `blur(70px) scale(1.35)` 降到 `blur(40px) scale(1.15)`：32px 颜色块拉伸后 40px 已足够柔，rasterization 成本约 1/3

### 验证（无头 Chrome + CDP）

测试桥新增 `addCoverSong()`：ID3v2.3 APIC 帧内嵌 1200×1200 细密条纹+文字图（缩略后一眼能看出糊）+ 80 帧静音 MPEG，验证脚本用 `setMode('one')` 锁住单曲循环避免短音频自动切到下一首。

实测（1440×900，headless **软件栅格化**，比真实浏览器更慢）：
- **封面**：`.cover-main img` `naturalWidth=1024, naturalHeight=1024`，`src` 是 blob（命中 `coverUrlHi` 路径），`complete=true`，`lyric-lines=3`（全部 LRC 组都渲染了）
- **动画**：
  - `p50: 5ms, p95: 5.1ms`——95% 帧都在 16ms 以内
  - 飞行结束附近（点击后 30~60 帧）**无任何 >32ms 的帧**，没有"收尾顿一下"
  - 仅有的 4 个长帧：飞行开始前 95ms（页面首次布局）、飞行中段 35ms（歌词布局 settle）、落地后 55/75ms（背景 blur 层 rasterization 触发）
  - `residualClones: 0`，`coverMainOpacity: "1"`，无 console 错误、无运行时异常
- 视觉：截图里 "ARIA 1200" 和同心圆条纹清晰可读（之前是糊的色块）

### 顺带
- 沙箱内 `vite build` 的 safe-delete 限制仍在，用 `--emptyOutDir false` 兜底（dist 里的过期文件是死链接，不影响）
- `.gitignore` 加 `.workbuddy/`（本机项目记忆不污染仓库）

## 会话 25：删 SongList 红竖条 eq + 歌词页背景渐变与飞行并行

### 用户反馈（截图 SongsView 首页，14 首歌，Lifetime Friend 在播放）
1. 「底部的这个拖拽条有 bug，鼠标悬浮在上面的时候会非常的卡顿抽搐，你直接把它去掉吧」
2. 「点击小封面跳转到歌词页面之后，歌词页面后面的模糊效果会延迟」

### 诊断
**问题 1 真相**：用户口中的「红色拖拽条」其实是当前播放行 `.eq` 均衡器图标（3 个 3px 宽的竖向红色 bar，`scaleY(0.4-1.0)` 1s 循环跳动）。叠加 `.song-row:hover { transform: translateX(2px) }`，整行 hover 平移的同时 eq 还在做 scaleY 错位跳跃，**视觉上就是「卡顿抽搐」**。用户从右侧时长远端看到的就是这个 12px 宽的迷你红竖条组，误认为是「拖拽条」。

放大裁剪（D:/verify-shots/user-shot-right.png / user-shot-rightmost.png）确认：Lifetime Friend 行 `4:22` 左侧的红色图标就是 `.eq`，不是任何 `position: fixed` 的拖拽条元素，CDP 全局探针也找不到 fixed 细高红元素。

**问题 2 真相**：歌词页背景渐变挂在 `<div class="bg-grad">`，原始逻辑在 `flyActive=true` 期间 `bgUrl=null`（不挂 DOM），fallback 通过 `pendingBg` 在 `settleFly` 之后才挂渐变 + `revealBg` 触发 520ms 透明度淡入。**飞行 560ms + 落地后 520ms 淡入**全靠飞行结束才开始算，用户感知「飞行结束还要等半秒」。

### 修改
1. **`src/components/SongList.vue`** 行 54-57：删除 `.col-duration` 中的 `<span class="eq">...</span>` 节点——当前播放行只显示 `formatDuration` 时长。`.song-row:hover` 的 `translateX(2px)` 保留（其他行仍有 hover 视觉反馈），只是没有了会跳动的 eq。PlayerBar 的 `.eq` **保留**（footer 不与 hover transform 冲突，仍作为「正在播放」的视觉信号）。
2. **`src/views/LyricsFullView.vue`**：
   - 删除 `pendingBg` 模块级变量
   - `apply()` 不再有 `if (flyActive.value) { ... }` 分支——渐变一算出立即 `bgUrl.value = gradient; revealBg()`
   - `settleFly()` 移除 pendingBg 处理
   - `flyIn()` 顶部新增：`if (bgUrl.value) revealBg()`——已缓存渐变时立即 reveal，让 280ms 透明度淡入与飞行 560ms 并行
   - `.bg-grad { transition: opacity 520ms → 280ms var(--ease-out); }`——淡入时长减半
   - 飞行期间视觉：bg-grad 会以 opacity 0→1 淡入，但被 `z-index:60` 的 flying clone 遮住；飞行结束 flying 删除后背景已在原地，不需要再等

### 验证
- `npm run build` 3.96s 通过（类型检查 ✓ + 构建 ✓）
- CDP `.song-row .col-duration .eq` = 0 个（确认 SongList eq 已删）
- 浅色主题 SongsView 截图（D:/verify-shots/fix1-songs-light.png）：Cover Song.mp3 行（当前播放，红雾高亮）右侧只有 `0:02` 时长，**没有任何红竖条**
- 歌词页 midflight 截图（t≈220ms，D:/verify-shots/fix3-lyrics-midflight.png）：飞行途中紫粉橙氛围渐变已可见 + flying clone 仍在 transform 移动中——**模糊背景与飞行完全并行**（修复前 220ms 时背景是纯深色）
- 歌词页 settled 截图（D:/verify-shots/fix2-lyrics-settled.png）：飞行结束左封面静止、模糊背景完全到位、歌词正确显示
- 无 console error

### 教训
- 当用户描述某个 UI 元素「bug」时，**先放大裁切截图再下结论**。本次误读「红色拖拽条」为某个全局 fixed 元素，实际是当前播放行只有 12px 宽的 `.eq`——小尺寸元素在远处很容易被错认为别的组件
- **叠层动画叠加 = 卡顿感**：eq 1s scaleY 跳动 + row hover 2px translateX = 视觉抖动。删除其中一个动画或消除冲突即可
