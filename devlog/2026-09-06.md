## 追加 9：自定义背景壁纸 + 通透程度（同日会话，会话 46）

### 需求与决策（用户拍板）
设置模块新增自定义背景壁纸；壁纸覆盖**全应用**（侧栏/播放条磨砂玻璃采样壁纸）；「通透程度」= 浓度（100% 完整原图 → 0% 不显示）；自动可读性遮罩（深色压暗/浅色提亮，随浓度联动）；全屏歌词页保持独立。

### 实现
- **存储**：图片 blob 存 IndexedDB kv（`kvSet('wallpaper', blob)`，不升 DB 版本），入库前用 `cover.downscale`（补了 export）压到长边 2560 JPEG q0.92；浓度标量走 localStorage `settings.wallpaperIntensity`（默认 100）。objectURL 单例复用，替换/清除时延迟 1s revoke 防交接闪断。新文件 `src/services/wallpaper.ts`（放 services 而非 composables——它是无组件上下文的单例服务）。
- **层与层级**：`.wallpaper-layer` 挂 `.app-shell` 首子节点，`position:fixed; inset:0; z-index:-1`——负 z-index 画在 body 画布背景之上、包括 static 侧栏在内的全部内容之下，玻璃 `backdrop-filter` 因此采样到壁纸。**CSS 注释写明硬约束：`.app-shell` 及祖先永远不得加 transform/filter/opacity（会变层叠上下文裁掉壁纸）**。`background-size:cover + center` 规避 object-fit。
- **浓度与遮罩**：浓度直接映射 `.wallpaper-img` 的 opacity（`--wallpaper-intensity` 由 settings watchEffect 写 :root，0~1 无单位）；遮罩 `.wallpaper-veil` 用 `opacity: calc(base + gain × intensity)`——dark `#000`（0.12+0.38i，100% 时 0.50）、light `#fff`（0.22+0.40i，100% 时 0.62），令牌两主题块各定义。壁纸异步加载后 0.5s 淡入，无闪白。
- **不透明层半透明**（`--wallpaper-bg-alpha: 0.86`，无壁纸时与纯色底视觉零变化）：`.detail-layer`（App.vue）、`.playlist-detail`、专辑/歌单详情头部渐变终点改 `color-mix(in srgb, var(--bg-base) calc(alpha*100%), transparent)`；**不加 backdrop-filter**（滚动容器实时 blur 有全屏卡顿前科）；排行榜吸顶表头保持不透明（下方滚动会透字）；歌词页不动。
- **设置页 UI**（外观 → 背景）：背景壁纸行（40px 缩略预览 + 选择/更换图片 + 清除）、壁纸通透程度滑杆（0-100%，仿歌词页 lyric-slider 填充样式，颜色走令牌）、说明文案；隐藏 `<input type="file" accept="image/*">`（全项目首个文件选择），`createImageBitmap` 预验证拦截 HEIC/损坏文件，失败提示「该图片无法使用，请换一张试试」。

### 验证（CDP headless）
页面内 canvas.toBlob 造图 → DataTransfer 塞 file input → dispatch change：壁纸层出现 + backgroundImage 为 blob: URL + kv 落库 ✅；浓度 50 → `--wallpaper-intensity` 0.5、img opacity 0.5、veil opacity 0.42（light 公式实算相符）✅；主题切换 veil `rgb(0,0,0)`↔`rgb(255,255,255)` ✅；专辑/歌单详情层 `color(srgb …/0.86)` ✅；歌词页仍 `#f6f3ec` ✅；清除后层消失 kv 为 null、浓度保留 ✅；浓度 0 → img opacity 0 ✅；PNG 接受 ✅。截图确认壁纸全应用透出、玻璃采样正常、文字可读。无异常。

### 踩坑
- **默认值 bug（截图抓到的）**：`Number(localStorage.getItem(key))` 键不存在时得 `Number(null)=0`，而 0 恰在 0-100 合法范围内 → 浓度默认变 0% 而非 100%。现有 loadXxx 都靠"0 不在合法范围"侥幸规避（字号 14-44 等），范围含 0 时必须显式判 null。已修 + 注释。
- 设置视图有 out-in 过渡，navigate 后 DOM 约 400ms 才挂载，CDP 断言要先等过渡结束（search 验证时同样手法）。

### 追加修复：100% 通透度仍雾蒙蒙 + 部分页面纯白背景未适配（用户反馈）
用户实测：壁纸 + 通透度 100% 后整体仍不够通透；部分页面与二级页面出现纯白背景。

**1. 遮罩曲线调弱**（main.css 两主题块）
- dark：黑遮罩 0.12+0.38i → **0.05+0.15i**（100% 时 0.50 → **0.20**）
- light：白遮罩 0.22+0.40i → **0.08+0.14i**（100% 时 0.62 → **0.22**）
- 100% 浓度语义 = 壁纸接近原图，可读性交给列表行/玻璃底的半透明底。

**2. 二级详情页"透壁纸不透一级界面"——两种方案，最终取 attachment:fixed**
- 方案一（已废弃）：`WallpaperUnderlay` 组件（层内 fixed 壁纸副本 z-index:-1）。CDP 截图发现**侧栏被壁纸盖住**：fixed 后代逃逸 `.detail-layer` 的 overflow 裁剪（详情层非其包含块），而详情层层叠上下文 z-index:5 整体画在 static 侧栏之上。探针证实 DOM 命中测试正常但渲染被盖。
- 方案二（定稿）：**删除组件**，详情层自身多层背景：
  ```css
  :root[data-wallpaper] .detail-layer, .playlist-detail {
    background: linear-gradient(var(--wallpaper-veil-cast), 同值),
                var(--wp-url) center / cover fixed no-repeat, var(--bg-base);
  }
  ```
  attachment:fixed → 背景相对视口绘制、cover 按视口取基准 = 与主壁纸层**像素级对齐**；背景只画在层盒内 = 不盖侧栏；滚动天然钉住。`--wp-url` 由 wallpaper.ts swapUrl 同步到 `:root`，遮罩成品色 `--wallpaper-veil-cast`（color-mix + calc 浓度公式）两主题块各定义。歌单头部渐变壁纸模式下改半透明。
- **3. 排行榜吸顶表头**：有壁纸时 `:root[data-wallpaper] .list-header` 改 `color-mix(bg-base 70%, transparent) + blur(24px)`，无壁纸实底不变。
