# 2026-09-11 开发日志

## 1. 胶囊播放条进度改「氛围光」（用户从 7 个方案中选定 E；当日第 1 轮，已被下面第 2 轮取代）

需求：现在的胶囊进度（悬停时沿外框爬升的深色弧线 + 粗圆头）不满意，要「无感、高级、富有创新」，先出方案再选。

**选型**：先做了一页方案对比（现状 + A 边缘流光 / B 液面 / C 内缘刻度 / D 磁吸游标 / E 氛围光 / F 声纹 / G 组合），每条都是 1:1 复刻的胶囊条、可拖动试手感、可切主题与常显悬停态。用户选 **E 氛围光**。

**落地（`PlayerBar.vue` + `main.css`）**：

- 进度不再是描在边框上的线，改成「**已播过的左半边被照亮**」：`.capsule-glow` 里两层 `.cg-fill`，底色是 `--bar-glow / -mid / -far` 三段主色薄雾（用 `color-mix` 从 `--accent` 派生，所以自定义主题换主色时自动跟随）。
- 右边界靠 `mask-image` 的线性渐变收尾：**常态 68px 软过渡**（远看只是一片渐变，不像控件）；**悬停/拖拽时交叉淡入 14px 紧边界**并浮出 1px `--bar-glow-edge` 分界线（`.cg-soft` / `.cg-tight` 两层互换 opacity —— 因为 `mask-image` 的位置本身不可过渡，所以用两层淡入淡出代替，避免引入 `filter: blur`）。
- 进度值 `--cp-p`（0~1）在 `main.css` 用 `@property` 注册成 `<number>`，于是 `timeupdate`（约 4Hz）的跳变被 `transition: --cp-p 160ms linear` 抹成连续推移；**拖拽期间 `.ring-dragging` 关掉该过渡**求 100% 跟手。
- 层叠：纯视觉层 `z-index:-1`（页脚 `z-index:6` 已自建层叠上下文）→ 落在玻璃之上、内容之下，所以不会盖住封面与文字；顶部 18px 的 `.capsule-progress` 退化成纯命中区（无内容无底色），继续避开「拖进度条抓到封面」的老坑。
- 删掉旧的 SVG 弧线（`CP_PATH` / `cp-*` 八条规则 / `cpFillStyle` 等），组件里不再有半透明线色令牌。

**验证**（`devlog/.shots-2026-09-11/verify-ambient-progress.mjs`，无头 Chrome + CDP 驱动本地 5180）：

- 结构/令牌：旧 `.cp-svg` 已消失；`z-index=-1`；`border-radius:999px`；`transition-property:--cp-p`；`--bar-glow` 在浅色解析为 `color(srgb .090 .145 .329 / .17)`（= #172554 17%）、深色为 `color(srgb .361 .486 .878 / .20)`（= #5c7ce0 20%）。
- 双 mask 停靠点：常态 `#000 calc(42.1% - 68px)`、悬停 `#000 calc(42.1% - 14px)`，收尾都在 `42.1%`。
- 悬停态互换：常态 soft=1 / tight=0 / edge=0 → 悬停 soft=0 / tight=1 / edge=1；拖拽时 `.ring-dragging` 为真且 `--cp-p` 跟到 0.72。
- 平滑性：播放中 `getAnimations()` 抓到 `--cp-p` 过渡，30 次采样得到 26 个不同的计算值（内联值 4Hz 才变），证明跳变确实被插值抹平。
- 几何：胶囊 760×66；光层 758×64（贴边框内侧）；热区 758×18。
- 截图：`light-rest-42` / `light-hover` / `light-drag-72` / `light-page-1x`（整页 1x 观感）/ `dark-rest-42` / `dark-hover`。控制台报错与页面异常均为 0。
- 像素抽查（2x 截图，条中线）：浅色已播侧 `rgb(219,221,228)` vs 未播侧 `rgb(255,255,255)`；深色 `rgb(32,38,55)` vs `rgb(17,17,17)` —— 正好是「薄雾」量级。

**两个调节杠杆**（后续微调直接改这两处）：

- 薄雾浓度 = `main.css` 两个主题块里的 `--bar-glow / -mid / -far` 百分比（浅色 17/11/3，深色 20/13/4）。
- 边界性格 = `.cg-soft` / `.cg-tight` 里的 `68px` / `14px`（越大越无感，越小越像仪表）。

## 2. 同日第 2 轮：氛围光保留 + 加一层「封面取色光粒子」（最终形态）

用户反馈三条：①氛围光的颜色要**从歌曲封面提取**；②末端那条 1px 竖线看着很怪；③氛围光和液态玻璃不太搭，想要**光粒子**的效果。中途又追加两条：粒子要**多且密集**、**小**，并且**氛围光要和原来一样保留**、粒子是加在光上面的。

**最终结构（`PlayerBar.vue`，三层都在同一个纯视觉层里）**：

- `.capsule-particles`（`inset:0` / `border-radius:999px` / `overflow:hidden` / `pointer-events:none` / `z-index:-1`）＝最外层容器，只负责裁剪与层叠；`--cp-p`（进度）与 `--pull`（聚拢系数）在这里写入。
- `.pt-field`＝进度 mask 层：`mask-image` 用 `--cp-p` 把「氛围光＋粒子」一起收在已播区间，收边宽度固定 **68px 软收尾**。
- `.pt-wash`＝氛围光（保留第 1 轮的观感，但颜色改成**封面色**）：`--fc` 注入封面明亮色，深色主题用 `--dust-mix:80% + #fff` 混白提亮、浅色主题用 `85% + #0b0b0d` 朝黑压一档；浓度由 `--wash-opacity`（浅 0.14 / 深 0.22）控制。
- `.pt` × `PARTICLE_COUNT(48)`＝浮在光上的光尘：`--dust-size`（浅 2.2px / 深 2.4px）、`--dust-opacity`（0.9 / 1）、`--dust-bloom`（浅 3px / 深 7px 外发光）。位置/漂移幅度/时长/聚拢权重**全部由下标用固定公式算出**（`x = 12 + t*740 + ((i*7)%9) - 4`、`y = 12 + ((i*13)%42)`、`dur = 11~19s`、`w = 0.24~0.64`、`c = i%3`），没有 `Math.random`，观感完全可复现；改 `PARTICLE_COUNT` 一个数就能整体加密/减疏（实测 48 颗时 x 间距 13.7~22.7px，42% 进度落在已播区间里 20 颗）。
- `.pt-halo`＝指针光晕：放在 mask 层**外面**（否则指针落在未播区时会被进度 mask 一起裁掉），跟随 `--cxpx`，透明度 = `--dust-halo-opacity` × `--pull`。
- 运动拆分：`transform` 跑 `@keyframes dust-drift` 慢漂移，`translate` 负责「向指针聚拢」`clamp(-34px, (cx-px)*w*pull, 34px)`——**位移封顶 34px**，指针离得远时是整片光尘一起轻轻侧倾，而不是把粒子搬到指针那里。

**取色链路改动**：

- `palette.extractBrightColors(blob, { lift })`：新增可选 `lift`（默认 0.25，现有调用方行为不变）；播放条用 `lift: 0` 拿原始饱和色，明暗交给主题令牌。
- `palette.sampleCoverColors(blob)`：新增，一次 `sampleBitmap` 同时产出 `base`（压暗主色）与 `bright`（原始明亮色），取代原来的 `coverBaseColor`（同一封面不再解码两次）。
- `paletteCache`：条目改为 `{ base, bright }`；新增 `brightOf()`（只读缓存）与 `brightColors()`（未缓存自动入队，同一 coverId 的并发调用共享同一个 Promise，4s 超时兜底 resolve `[]`）；`get/colorOf/prime/primeNow` 签名不变。
- `PlayerBar` 侧：`watch([coverId, settings.ambientGlow])` → `primeNow` + `await brightColors`（带序号守卫丢弃过期结果）→ 注入 `--fc`；切歌靠粒子自身的 `transition: background 600ms` 淡换色，不重建 DOM；取色失败/灰阶封面回落 `var(--accent)`。

**验证**（`devlog/.shots-2026-09-11/verify-dust-progress.mjs`）：48 颗 ✓；`.pt-field` mask 停靠点 `calc(42.1% - 68px)`（悬停/拖拽仍是 68px，见下）✓；`.pt-wash` 渲染且 opacity 0.14 ✓；粒子尺寸 2.19px、暂停后透明度 0.648 = 0.9×0.72 ✓；悬停 `--pull=1`、光晕中心 x 与指针 x 完全相等（318 = 318）✓；拖拽 seek 仍精确落到 0.72 ✓；换歌后粒子颜色从紫/米变成琥珀/红 ✓；`prefers-reduced-motion` 下 `animation-name: none` ✓；切标准条后无粒子层 ✓；控制台报错与页面异常 0 ✓。截图：`dust-light-rest/hover/drag`、`dust-dark-rest/hover`、`dust-light-page-1x`。

**四个调节杠杆**（后续微调只动这些）：

- 密度 = `PlayerBar.vue` 的 `PARTICLE_COUNT`（48 → 更多更密）。
- 颗粒大小/浓淡/发光 = `main.css` 两主题的 `--dust-size` / `--dust-opacity` / `--dust-bloom`。
- 氛围光浓度 = `main.css` 两主题的 `--wash-opacity`（浅 0.14 / 深 0.22）。
- 收边软硬 = `.pt-field` 里的 `--pt-fall`（现固定 68px）。

## 遇到的问题

1. **光层盖在文字上**：`.capsule-glow` 若用默认 `z-index:auto`，绝对定位层会画在普通流内容之上。改用 `z-index:-1`——页脚已经是层叠上下文（`position:absolute` + `z-index:6`），负值正好落在「玻璃底 → 光层 → 内容」的正确顺序，且不必给 `.track/.controls/.aux` 加 `position`（避免改动队列面板的定位上下文）。
2. **`mask-image` 停靠点不可过渡**：直接用 `transition: mask-image` 无效。改成软/紧两层 `.cg-fill` 互换 `opacity`（各 220ms）——观感等价，且全程只有 opacity 与 mask 位置变化，没有引入任何模糊层。
3. **进度跳变**：`timeupdate` 约 4Hz，直接绑 mask 位置会一跳一跳。用 `@property` 把 `--cp-p` 注册成可插值数值解决；这也是项目里第一处 `@property` 注册（已写进 03-设计规范 §3 附近）。
4. **验证环境两个坑**：①新 profile 默认是「标准条」（`settings.playerStyle` 未设 = standard），脚本要先写 localStorage 再重载，否则找不到胶囊层；②`audio` 元素是游离的 `new Audio()`，取不到 DOM，seek/暂停改用测试桥的 `seek()` / `toggle()`。
5. **指针光晕被进度 mask 一起裁掉**：光晕原本和粒子同层，指针落在未播区时整个光晕被 mask 收光。改成两层结构——`.pt-field` 只装「氛围光＋粒子」并挂 mask，`.pt-halo` 提到 mask 层之外（仍在裁剪容器内），指针在哪都看得见。
6. **悬停收紧 mask 会重新读成一条硬边**：第 1 轮把收边从 68px 收到 14px 当「可拖暗示」，但配上封面色氛围光后，末端就是一条明显的竖切边——正是用户否掉竖线的那种观感。改法：收边固定 68px，「可拖」完全交给粒子聚拢＋指针光晕，`--pt-fall` 只留作微调杠杆。
7. **粒子规格返工两轮**：初版 12 颗 2.6/3.6px（用户：太少、不明显）→ 24 颗 → 30 颗 3.2/3.6px（用户：太大了、要多且密集）→ 最终 48 颗 2.2/2.4px。教训：这类「星尘感」的判断标准是**小颗粒 × 高密度**，单颗尺寸往大调是错方向；密度用 `PARTICLE_COUNT` 一个数字控制，方便按用户反馈快速收敛。
8. **指针光晕不要动 `left`**：用 `left: var(--cxpx)` 配 transition 会走布局且抖动；改用 `translate: calc(var(--cxpx) - 50%) -50%`，纯合成、零布局。
