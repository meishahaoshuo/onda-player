### 2. 专辑/艺术家详情页的返回钮与窗口按钮重合（点击被吞）

- **修法**：新增令牌 `--win-safe-r: 144px`（按钮组 3×40 + 右栅格 24）表示右上角保留带；两个详情视图在桌面端整体左移让出该带：`html.desktop-glass .header-close { right: calc(var(--win-safe-r) - 16px) }`（144 − 24 卡片右缘内缩 + 8 间隙 = 128）。网页端无窗口按钮，保持贴角

### 3. 启动过场开头卡顿
- **探针测量**（注入脚本记录 rAF 帧间隔 + `longtask` + 各阶段时刻）：dev 下 splash 与 app-shell 同在 **294ms** 才进 DOM，波浪动画 **297ms** 才起步；一个 **107ms 长任务**卡在 162~296ms
- **根因**：`<BootSplash />` 原为 `.app-shell` 最后一个子元素，其 `onMounted` 必须等**整棵应用树挂载完**；而静态 import 会把整棵应用树打进同一 chunk，浏览器必须先求值完才能画第一帧 → 过场只能一起等
- **修法**（三处配合）：
  1. `main.ts`：过场先独立挂载（`createApp(BootSplash).mount(host)`），**主应用改动态 import**（新增 `src/boot.ts` 导出 `mountApp`）→ 入口 chunk 只剩 vue + 过场（产物 `index` 406KB → 83.6KB，app 拆到 `boot` chunk 323KB）
  2. 主应用挂载改由过场在**生长拍收笔后**（840ms）派发的 `onda:splash-grown` 事件触发 → 那个 ~100ms 挂载长任务不再落在波浪生长期间；reduced-motion 无过场时 setup 阶段立即派发同一事件放行；另设 1800ms 兜底
  3. 侧栏品牌的隐藏从"JS 查元素设内联 style"改为全局规则 `html.is-booting .sidebar .brand { opacity: 0 }`，且 `is-booting` 改在**过场 setup 阶段**挂上——内联方案要等侧边栏挂载后才查得到元素，元素会先以 opacity:1 渲染一帧再被改掉（闪一下）
- **实测对比（dev）**：splash 进 DOM **294ms → 50ms**；波浪动画起步 **297ms → 78ms**；生长期（0~840ms）帧尖峰 **4 次（含 133/142ms）→ 0 次**；应用挂载 294ms → 1045ms（生长收笔之后）；>100ms 帧 3 → 1
- 遗留：应用挂载的 ~80ms 长任务现落在 965~1045ms（拼合抖动期间），抖动中掉帧观感损耗远小于平滑生长期间；无头 Chrome 软件渲染会放大绘制耗时，真机有 GPU 时更轻

## 十三、修复「队列面板点第二次关不掉」+ 统一下队列面板在两态的位置

### 13.1 点队列图标关不掉（根因：一次点击被拆成两步）
`PlayerBar.vue` 的 `onBarPointerDown`（绑在根 `.player-bar` 的 `@pointerdown`）**没有排除队列按钮**：
```
pointerdown → if (queueOpen) { queueOpen = false }   // 先关掉
click        → queueOpen = !queueOpen                // 又变回 true
```
一次点击里关了又开，表现为「点第二次关不掉、反而重新出现一次」。文档级捕获监听 `onDocPointerDown` 本来就排除了 `[data-queue-toggle]`，漏的是根元素这一个。

**修法**：在 `onBarPointerDown` 开头先让开 `[data-queue-toggle]` 与 `.queue-panel`（与 `onDocPointerDown` 的排除项保持一致）。

**验证（`verify-queue.mjs`）**：必须用 CDP `Input.dispatchMouseEvent` 发**真实指针事件**——`element.click()` 只派发 click、不产生 pointerdown，根本测不出这个 bug。结果：1 开 → 2 关 → 3 再开 → 4 再关 ✓；点空白处收起 ✓；点面板内的行不收起 ✓；点「上一曲」收起且不误 seek ✓；清空按钮清空并收起 ✓；`exceptions: []`。

### 13.2 队列面板在两态位置不一致（差 163px）
`.queue-panel` 是 `right: 16px` **相对播放条自身**。标准态条子满宽（0~1084），面板右缘落 1068（距窗口右 16px）；**胶囊态条子只有 760px 居中（162~922）**，面板就跟着缩到屏幕中部（右缘 905，距窗口右 **179px**）——切样式时面板横向跳 163px。

**修法**：胶囊态增加补偿，把基准从「条子右缘」改回「窗口右缘」：
```css
.player-bar.capsule .queue-panel { right: calc(16px - 50vw + 50%) }
```
原理：条子水平中心 = 窗口中心（`left:50%` + `translateX(-50%)`），其半宽正好是 `50%`（绝对定位子元素的百分比基准 = 条子 padding box）。
**实测**：两态 `gapPanelRightToWindow` 均为 **16**，面板中心均为 878，`差: 0`；1084px 下 `scrollWidth == innerWidth`（向右溢出条子未撑出横向滚动）；820px 窄窗下面板右缘 804 = 820−16，仍在窗口内。

### 13.3 一并确认（非 bug）
压测数据里「点队列某行后队列从 6 首变 1 首」是**测试假象**：`player.ts:88` 在文件读不到时 `queue.splice(i,1)` 并递归跳下一首，而 `stressAlbums` 注入的是合成记录、没有真实文件，于是被逐首剔掉。真实文件不受影响。

## 十七、专辑/艺术家过渡整体放慢到 1.35×（用户要求「优雅丝滑」）

**先量基线**（探针 `probe-transition-time.mjs`：页面内 rAF 计时，从 `ui.dolly` 变非 idle 起、到回到 idle 止，规避 CDP 往返误差）：
- 进入 **547ms** / 返回 **495ms**（实测为**非 lite** 档：若 lite 生效会 ×0.7，550 左右的值反推可知未生效）

**改法（一处）**：编排器加了全局缩放 `const SPEED = 1.35`，只改 `dur()`：
```js
function dur(ms) { return lite ? ms * 0.7 * SPEED : ms * SPEED }
```

## 十八、修复：封面被裁切时，过渡动画盖住顶栏

**复现与量化**（探针 `probe-fold-overflow.mjs`：把 `.view-body` 滚 90px 让首行卡片被裁掉半截，再点进去、点返回，用 rAF 采样 `.detail-layer` 的 `rect.top`）：
- 顶栏下缘（`--head-band-h`）= **62**
- 退场期间折叠层 `rect.top` **最低到 −29.7px**，**58 帧**越过裁切线，且 t=93ms 时 `opacity: 1`（**不透明地盖上去**）

**根因**：卡片被滚出视口一部分时，`getBoundingClientRect().top` 会跑到顶栏底下（实测 rawTop = **−48px**）。而两个过渡产物都照着这个**未裁切**的矩形飞：
1. `foldLayerOut` —— 用 `transformOrigin:'0 0'` + `translate(tx, ty)`，`ty = cardRect.top − layerBox.top` 为负 → 整层向上顶出 62 这条线
2. `flyCoverBack` 的克隆 —— `position: fixed; z-index: 70` 挂在 `body` 上，落点也是这个越界矩形

**修法**（`pageTransition.ts`，一处策略）：新增 `topClipLine()`（取网格滚动宿主 `.view-body` 顶边）+ `clampTop(b)`（按裁切线夹紧矩形，**高度同步收缩**，只保留可见部分），在三处应用：`origin.rect`（进入飞行源）、`origin.cardRect`（折叠/析出目标）、`playAlbumExit` 里的 `to`（返回飞行落点）。点一点处理，下游全部自动受约束。点击永远落在可见区，故飞行原点仍在夹紧后的矩形内。

**验证**（`verify-clip-transition.mjs`）：四个用例全部 `overflowSamples: 0`、`minTop` 恰好等于 62；完全可见卡片的回归用例正常；结束态 `dolly: idle`、无残留 `.page-flight`、卡片 `opacity: 1`；`exceptions: []`。

## 十九、重做顶部越界修复：从「挪落点」改为「裁掉越界部分」

### 上一版为什么不行（用户反馈：动画卡一下、再回到原来的位置）
上一版把 `cardRect` / 飞行的 `to` **按裁切线夹紧**（抬高落点、收缩高度）。副作用：
- 克隆/折叠层收尾落在 y=62（夹紧后），而真实卡片在 y=−48 → **收尾瞬间卡片一跳 48px 回到原位**，看起来就是"卡一下再弹回去"

### 两种策略的对比
| | 做法 | 结果 |
|---|---|---|
| ❌ 挪落点 | 把目标矩形夹到裁切线内 | 不盖顶栏，但**收尾跳变** |
| ✅ 裁越界 | 落点照**真实**矩形算，越界部分在绘制层裁掉 | 不盖顶栏，且**零跳变** |

### 本次实现（两处裁切）
1. **详情层**：`App.vue` 新增 `.detail-clip` 容器（`position:absolute; top:var(--head-band-h); inset 其余 0; overflow:hidden; pointer-events:none`，子元素恢复 `pointer-events:auto`），两个详情视图挪进去；`.detail-layer` 由 `top:var(--head-band-h)` 改回 `inset:0`。折叠时整层被 translate 到卡片矩形，超出 62 的部分在这里被裁
2. **飞行克隆**：`pageTransition.ts` 新增 `flightHost()` —— `position:fixed; inset:0; z-index:70; clip-path: inset(62px 0 0 0)`，克隆由 `document.body` 改挂到这里。容器**必须铺满视口**：`clip-path` 会让它成为 fixed 子元素的包含块，从 0 起坐标才不会整体偏移
3. 撤掉全部 `clampTop`（保留 `topClipLine()` 供 `flightHost` 计算裁切线）

### 验证
- **像素级**（`verify-clip-pixels.mjs`，新增可复用 `png-dec.mjs`）：退场期间顶栏那一条（0~62px）**逐像素不变** —— 有裁切时 `maxDiff=0 / 脏像素 0`；**A/B 对照**把裁切临时关掉（`overflow:visible` + `clipPath:none`）立刻 `maxDiff=40 / 脏像素 2766`，证明测法敏感、裁切正是起作用的一环
  - ⚠️ 测法坑：点「返回」会让鼠标**悬停在顶栏的返回钮上**，hover 态变化会污染像素对比 → 截图前必须把鼠标移到中性位置并等 hover 收尾
- **落点零跳变**（`verify-clip-jump.mjs`）：克隆最后一帧 vs 真实卡片封面 → `dTop/dLeft/dW/dH` **全为 0**
- **回归**：导航返回（`dolly: exit` → 层卸载）✓；详情层滚动 `layerTop` 仍为 62、可滚动、`scrollTop` 生效 ✓；结束态 `dolly: idle`、无残留 `.page-flight` ✓；`exceptions: []`

**问题**：`.head-back` 此前是一枚**裸箭头**（只有 hover 才出现 `--bg-hover` 圆角底），在浅色顶栏上与背景几乎融在一起，读不出「可点」。

**改动**（`App.vue` 的 `.head-back`，共 3 行）：
- 常驻 `background: var(--bg-hover)` + `border: 1px solid var(--border-subtle)` → 与右侧搜索框**同材质**，一眼看出是一颗按钮
- hover（`:not(:disabled)`）：`--bg-active` 底 + `--accent` 描边 + `--accent` 图标（原来只有 `--bg-hover` 底，现在静置态已用它，必须换一档才看得出悬停）
- `transition` 补 `border-color`；`disabled` 的 `opacity: .3` 不动

**为什么用 `box-sizing` 安全**：`main.css` 有全局 `*{box-sizing:border-box}`，加边框不改变 36×36 外框，顶栏几何零位移（实测 rect 与改前一致）。`button{border:none}` 是元素选择器，被 `.head-back` 类选择器正常覆盖。

**实测（`verify-head-back.mjs` + `verify-head-back-tight.mjs`，浅/深 + 静置/悬停/置灰）**：
- 几何未变：`rect = {x:650, y:20, w:36, h:36}`，与搜索框间距仍 **8px**，圆角仍 10px
- 浅色静置 `1px solid rgba(0,0,0,.08)` / 底 `rgba(0,0,0,.05)`；深色 `rgba(255,255,255,.12)` / `.08` —— 都用令牌，无硬编码
- 浅色 hover → 描边 `rgb(23,37,84)`、底 `rgba(23,37,84,.1)`、图标同色
- 置灰（无上一级）`opacity: .3` → 整个框几乎隐去、只剩淡箭头，退回原「幽灵」观感（刻意：不可用时不该假装可点）
- `consoleErrors: []`（首轮有一条 `Failed to fetch dynamically imported module boot.ts?t=…` 属 dev-server HMR 失效时间戳的瞬时噪声，重载后不再出现，与本次改动无关）

## 二十、二级浮层补齐「弹出」动画（用户要求：这类二级界面都加上弹出动画）

**盘点结果**（全站条件渲染浮层共 8 处）：队列面板 / 添加歌曲弹层 / 封面选择 / 新建歌单弹窗 / 排序下拉 / 更多操作下拉 / 批量「添加到歌单」面板 / 专辑页「添加到歌单」面板 / 歌曲右键菜单及二级面板 / 歌单名右键菜单 / 歌词页字号菜单。
**当时的状态**：弹窗（手机上的 modal）与歌词页 `fs-pop` 有动画；**歌单名右键菜单的 `.menu-*` CSS 写了但模板里根本没有 `<Transition>`（等于没动画）**；歌曲菜单的二级面板（添加到歌单列表）是裸 `v-if`；4 个组件各自复制了一份 `.menu-*`，参数还不一致（0.12s / 0.08s / 0.96 vs 0.92）。

**做法**：
- 把 `.menu-*` 提到 `main.css` 全局一份：进 `scale(.9) translateY(-6px)` + `--ease-spring` + `--dur-med`(220ms)，出 `scale(.96)`/120ms。**组件内的 4 份复制全部删除**
- 补上缺失的过渡：歌单名右键菜单加 `<Transition name="menu" appear>`；歌曲菜单的二级面板加同名过渡；排序下拉补 `<Transition>`
- 各面板补 `transform-origin`：右上角下拉 `top right`（更多操作 / 排序 / 添加歌单 / 专辑添加歌单）、跟随点击点或向右展开 `top left`（歌曲菜单 / 歌单菜单 / 二级面板）、居中弹窗用默认 center
- **两个关键坑**：
  1. `v-if` 的层级不对就没动画 —— `<Transition>` 需要有条件的子节点；把过渡包在「全屏遮罩层」上会连菜单一起缩放位移（原来是靠 `.menu-enter-from .song-menu` 后代选择器绕开的）→ 改成：遮罩层不做动画（全透明无需动画），过渡只包面板本体，两者同时挂载时用 `appear`
  2. 全局补 `@media (prefers-reduced-motion: reduce)` → `.pop-*` / `.menu-*` 关闭过渡

**验证**（`verify-pop-in.mjs`）：逐个触发后 30ms 采样 `el.getAnimations().length` + 计算样式。8 处全部 `anims=2`、`transitionDuration 0.22s`、透明度从 ~0.10 涨到 1.00、`transform-origin` 符合锚点；`exceptions: []`。截图 `140/141`。
**文档**：`docs/03-设计规范.md` §3.1 补了 `.menu-*` 的适用场景、`transform-origin` 约定与「过渡挂面板本体 / 同时挂载要 appear」两条坑。

## 二十二、桌面端 1.0.0 收口：版本统一 / 启动窗口 / 🔴 SW 缓存把界面锁在旧版本

### 22.1 打包配置收口
- 版本号原有**四处漂移**（`tauri.conf.json` 0.2.2、`package.json` 0.1.0、`Cargo.toml` 0.1.0、`package-lock.json` 两处）→ 统一 **1.0.0**；`tauri.conf.json` 的 `version` 改为 **`"../package.json"`**（Tauri schema 官方支持），此后只改 package.json 一处
- `Cargo.toml` 清脚手架残留（`description = "A Tauri App"` / `authors = ["you"]`）；`bundle` 补 `publisher: "Onda Player"`（不写会默认取 identifier 第二段 `ondaplayer`）、`copyright`、`nsis.languages: ["SimpChinese"]`
- `[profile.release]`：`lto = true` + `codegen-units = 1` + `strip = true`。**未加 `panic = "abort"`**（不改变 panic 行为）、**未动 opt-level**（不牺牲运行时性能）
- **实测**：装包 **27,266,287 → 2,234,122 B（26.0 → 2.13 MB）**，app.exe 8.8 MB。主因是 `strip` 去掉符号表 —— 之前那个 26 MB 装包对应的正是未 strip 的大二进制。打包耗时 9m44s

### 22.2 启动窗口「先在右下角、再跳中间」
- **根因**：窗口配置**既无 `center` 也无 `position`** → Windows 给默认位置；而定位逻辑在 `App.vue` 的 `onMounted`（要等过场生长拍收笔 840ms 才挂载）→ 窗口先按默认位置露脸，约 1 秒后才跳
- **修法**：
  1. `tauri.conf.json` 加 **`center: true` + `visible: false`**（窗口出生即隐藏、且居中）
  2. 新增 `desktop.ts` 的 **`primeWindow()`**：恢复记忆位置/尺寸 → `show()`；在 `main.ts` **挂载过场后立即调用**
  3. `initDesktop()` 卸掉定位职责，只留状态记忆 / 托盘 / 磨砂
  4. Rust 兜底：`setup` 起 2 秒线程，未收到前端 `mark_window_primed` 回执则强制 `center + show`（防前端脚本挂掉导致窗口永不出现、进程却还在托盘里）
- ⚠️ **为什么必须紧贴过场挂载**：窗口隐藏时 Chromium 把 `setTimeout` 压到 1s 粒度，而 `BootSplash` 的时间轴正是 `setTimeout` 驱动（`later()`）—— 隐藏时间必须压在百毫秒内，否则整条过场时间轴被拉长
- 验证：`tasklist /FO CSV /V` 显示进程 Running、窗口标题 `Onda Player`（本机无截图手段，见 §22.5）

### 22.3 🔴 根因：Service Worker 把旧界面一直喂给页面
**现象**：用户反馈「安装包不是我修改好的版本，是之前的老版本」。

**先排除的方向**（都成立，所以都不是原因）：
- `dist/` 含最新特征串（「批量操作」「播放全部」）→ 构建产物是新的
- `app.exe` 进程正常、窗口标题正确 → 可执行文件是新的
- `%LOCALAPPDATA%\Onda Player` **不存在** → 本机从未安装过，谈不上「已装旧版」

**真因**：`%LOCALAPPDATA%\com.ondaplayer.app\EBWebView\Default\Service Worker\CacheStorage` 里存着**更早版本的外壳**。

**决定性证据**：缓存中的 index.html 引用 `index-Bmk6GFMu.js` 等 **6 个旧 hash**，且**完全没有 boot chunk**（`boot-*.js` 是本次会话才拆出来的）；而当前 dist 的入口是 `index-DjJwgYiA.js` + `boot-DbBeRsB6.js` —— 两边完全对不上。

**机制**：`public/sw.js` 的 fetch 对 `pathname.includes('.')` 走**缓存优先**；`navigate` 分支虽写了网络优先，但 `fetch(req)` 在 Tauri 自定义协议下**拿不到资源** → 落到 `.catch()` → `caches.match('/')` → 永远返回旧外壳。
**为什么一直没被发现**：日常验收全在 `tauri dev`（dev 不注册 SW），只有 release 安装版会中招。

**修法（两处，互补）**：
1. `lib.rs` 新增 `purge_stale_service_worker(identifier)`，在 **`run()` 最开头**调用 —— 必须在 WebView2 初始化**之前**，否则数据目录被占用、文件锁住删不掉（放 `setup` 回调里已经太晚）。顺带把 `tauri::generate_context!()` 提前成局部变量，避免重复求值
2. `pwa.ts` 的 `setupPwa()`：`isDesktop` 时**不注册 SW**，并主动 `getRegistrations().unregister()` + 清空 `caches` 兜底

**安全性**：只删 `Service Worker` 子目录；歌曲库、播放列表在同级的 `IndexedDB` 里，不受影响。
**临时验证**：把该目录 `mv` 成 `Service Worker.stale-bak`（**重命名而非删除**，可随时回滚），重启后界面即为最新。

### 22.4 被证伪的优化（未做，记录以免重犯）
原计划把 `HI_RES_LRU_LIMIT` 由 32 降到 12「省约 134MB」。**代码核实后不成立**：`library.ts` 的 `hiResUrls` 是 `Map<string, string>`，存的是 **objectURL**，指向压缩后的 1024 边 JPEG Blob，**不是解码位图** —— 32 张最坏也只有几 MB。而且下调会让用户在专辑/歌单间来回浏览时反复驱逐命中项、触发重解析音频头 + 重新缩放，**收益为负**。已放弃。

### 22.5 本机环境坑（协作时必读）
- `~/.rustup` 是**断链符号链接**（指向已不存在的 `D:\项目文件\.rustup`）→ cargo 报 `could not create home directory ... os error 183`。真实工具链在 **`RUSTUP_HOME=D:\rust\rustup`、`CARGO_HOME=D:\rust\cargo`**，跑 cargo 必须显式带上
- 上述路径在项目目录之外，**沙箱访问不到** → 编译类命令需 `dangerouslyDisableSandbox`
- 本机 **PowerShell 工具被安全策略拦截**（`Add-Type` 被判为运行时编译 .NET 代码）→ 无法用 .NET 截屏；`PIL` 亦未安装 → **桌面窗口的视觉验证暂缺自动化手段**，只能靠 `tasklist /FO CSV /V` 读窗口标题
