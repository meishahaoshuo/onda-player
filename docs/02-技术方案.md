# 02 技术方案

## 1. 技术栈

| 领域 | 选型 | 版本 | 说明 |
|---|---|---|---|
| 框架 | Vue 3 + TypeScript | ^3.5 | 组合式 API（`<script setup>`） |
| 构建 | Vite | ^7 | dev / build / preview |
| 状态管理 | Pinia | ^3 | player / library / settings / stats / favorites / playlist / ui 等 store |
| 文件接入 | File System Access API | 原生 | `showDirectoryPicker` + IndexedDB 存句柄 |
| 元数据 | music-metadata | ^11 | `parseBlob` 解析 File 对象 |
| 本地存储 | idb | ^8 | IndexedDB Promise 封装 |
| 播放 | HTMLAudioElement | 原生 | 单例 audio，队列由 store 管理 |
| 系统集成 | MediaSession API | 原生 | 媒体浮窗 / 媒体键 |
| 桌面化 | Service Worker + PWA | 原生 | 手写 `public/sw.js`（仅生产注册）实现可安装条件与离线外壳；`beforeinstallprompt` 接入设置页安装入口，不引入 workbox 等构建期依赖 |
| 桌面壳 | Tauri 2 | ^2 | Windows 桌面端（第 8 阶段）；WebView2 内核，`npm run desktop`；`@tauri-apps/cli` 为 devDependency |

浏览器要求：Chrome / Edge 86+（File System Access API）。页面必须通过 http(s) 访问（`npm run dev` 的 localhost 即可），不支持 `file://` 直接打开。

### 桌面端（第 8 阶段）重要说明

PoC 实测（2026-09-13，详见 devlog）：**WebView2 有意禁用整套 File System Access API**（`showDirectoryPicker` 为 `undefined`，微软文档明示不支持），因此桌面端不依赖 FSA，文件接入改走原生路径方案：

- 选目录：`tauri-plugin-dialog` 原生文件夹选择对话框
- 枚举：Rust 侧递归扫描，返回 `{ path, size, mtime }` 清单
- 播放：注册自定义 `media://` 协议，Rust 侧按 Range 流式返回文件，`audio.src` 直接指向协议 URL（整文件不进内存）
- 标签解析：按需读文件字节为 `Uint8Array` → `parseBuffer`，封面缩略链路不变
- 持久化：IndexedDB 存目录**路径字符串**取代 FSA 句柄——桌面端不再有每次启动的授权确认
- 歌词：同目录 `<同名>.lrc` 改由 Rust 侧按路径读取

网页版（浏览器形态）继续使用 FSA 方案；平台差异收敛在 `services/fs.ts` / `scanner.ts` / `player.ts` 服务层，上层界面与 store 不感知运行形态。

> 窗口级透出桌面的材质（磨砂/透明）曾于 2026-09-25 尝试四轮后**按用户决定整体移除**——窗口恒为不透明，`--bg-base` 铺实色。过程与教训（webview 图层 alpha、系统合成层「API 成功」≠「渲染了」）见 devlog 2026-09-25 与 docs/03 §2。

#### 桌面端开发工作流（日常必读）

**一份源码两个壳**：桌面端不复制代码，`tauri.conf.json` 的 `frontendDist` 直接指向 `../dist`，`devUrl` 指向 `http://localhost:5180`。所以改 `src/` 里任何文件，网页端和桌面端同时都改了。

**两个命令，性质完全不同，别混用**：

| 命令 | 作用 | 何时用 |
|---|---|---|
| `npm run desktop` | `tauri dev`：连 5180 的 Vite dev server 开窗口，**前端改动热更新即时生效，不产出安装包** | 日常开发，几乎总是用这个 |
| `npm run desktop:build` | `tauri build`：release 编译 + NSIS 打包，产出 `Onda Player_x.y.z_x64-setup.exe` | 只有要分发/长期使用时 |

**改动与生效代价**：

- 改 `src/` 下任何前端代码 → 保存即生效（HMR），窗口不用重开
- 改 `src-tauri/` 下 Rust 代码（`lib.rs` / `Cargo.toml` / `tauri.conf.json`）→ tauri dev 自动增量重编译并重启窗口，通常几十秒；改 `tauri.conf.json` 同样自动重启
- **已安装的桌面版永远不会自动同步**：它内嵌的是打包那一刻的 dist 快照，要更新必须 `npm run desktop:build` 出新安装包重装

**启动链与注意事项**：

1. 先确保 Vite dev server 在跑（`npm run dev`，5180），否则 tauri dev 的窗口会停在 `chrome-error` 错误页——此时整套 API 都不可用，极易误判成功能坏了
2. 双击项目根目录的 `开发桌面端.bat` 可一键完成：检测/启动 5180 → 检查实例冲突 → 启动 `npm run desktop`
3. **单实例锁冲突**：开发实例（`src-tauri/target/debug/app.exe`）与已安装版共用同一 identifier，已安装版开着时 dev 实例会**启动后立刻静默退出**（exit 0，现象极具迷惑性）。开发前先退出已安装的 Onda Player
4. 纯前端改动用 `npm run dev` 在浏览器里看更快，且天然对两端都生效；只有需要验证窗口级行为（标题栏/磨砂/托盘/拖拽/原生文件对话框）才必须开桌面窗口

## 3. IndexedDB 数据模型（库名 `music-player`）

| Object Store | Key | Value | 说明 |
|---|---|---|---|
| `handles` | `root:<id>` | FileSystemDirectoryHandle | 音乐文件夹句柄；`kv` 中存 `folderOrder` 维护顺序 |
| `songs` | `path`（相对根路径） | SongRecord | 全量歌曲元数据 |
| `covers` | `coverId`（专辑名+专辑艺术家哈希） | Blob | 缩略图（256px，JPEG） |
| `playlists` | `id` | PlaylistRecord | 歌单及内含歌曲 path 顺序数组 |
| `kv` | string | unknown | 设置、上次播放状态（队列 path、进度、音量、模式） |
| `stats` | `path` | `{ playCount, lastPlayedAt }` | 播放统计（DB v2）；听满 30 秒或进度 50%（先到）计 1 次 |
| `favorites` | `path` | `{ addedAt }` | 我喜欢的音乐（DB v2） |

SongRecord 主要字段：

```ts
{
  path: string          // 相对根路径，主键
  rootId: string        // 所属文件夹句柄 id
  fileName: string
  title: string         // 无标签时用文件名
  artist: string        // 多艺术家以 " / " 连接
  album: string         // 无标签时 "未知专辑"
  albumArtist: string
  genre: string
  year: number | null
  trackNo: number | null
  discNo: number | null
  durationSec: number
  bitrateKbps: number | null
  sampleRateHz: number | null
  bitsPerSample: number | null
  container: string     // flac / mp3 / ogg ...
  fileSize: number
  mtimeMs: number       // 用于增量扫描
  hasCover: boolean
  coverId: string | null
}
```

## 4. 关键流程

### 4.1 扫描
1. 从 `handles` 恢复句柄 → `requestPermission` 确认
2. 递归枚举目录（跳过隐藏目录），过滤扩展名得到音频文件清单
3. 与 `songs` 现有记录按 path 对比：大小+mtime 未变的直接跳过；新增/变化的 `parseBlob` 解析；根目录里已消失的删除记录
4. 封面按 `专辑名+专辑艺术家` 去重后缩略并写入 `covers`
5. 扫描在主线程分批执行（每批若干文件让出事件循环），保证 UI 可交互、可取消

### 4.2 播放
- 播放 = `audio.src = URL.createObjectURL(file)`（由句柄实时 `getFile()`），播完按模式决定下一曲
- 队列是 path 数组 + 当前索引；随机播放洗牌但不重复直到一轮结束
- MediaSession：`metadata`（标题/艺术家/专辑/封面 artwork）+ 四个 action handler
- 刷新恢复：从 `kv` 读队列与进度，恢复后处于暂停态等待用户点击播放

### 4.3 歌词
- 播放时尝试读取同目录 `<同名>.lrc`，按 `[mm:ss.xx]` 解析时间轴
- 时间戳差 < 50ms 的相邻行合并为一组（原文 + 翻译/罗马音）
- 无歌词或解析失败则歌词页显示占位文案

## 5. 已知限制

- APE / TTA 等浏览器不支持的格式无法播放，扫描时跳过并计入"已跳过"数量
- 网页无法做到窗口级磨砂（透出桌面），磨砂只作用于页面内部
- 浏览器标签页关闭后句柄权限需确认一次（浏览器安全机制，无法绕过）
- Service Worker 只缓存应用外壳（HTML/JS/CSS/图标），不缓存任何音频与歌词内容；音乐文件始终由 File System Access 句柄实时读取（blob URL 本就不经过 SW）
- 「安装到桌面」需 Chrome / Edge 且页面通过 localhost 或 https 访问
